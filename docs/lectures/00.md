# 00 全局地图与阅读方法

## 00.1 教学数据库的目标与非目标

toyDB 是用 Rust 写的教学用分布式 SQL 数据库。作者在 README 里写明：目标是**简单、可理解、功能正确**。性能、水平扩展、生产级可用性明确不是目标。

因此代码里会出现这些取舍：

- 单文件 BitCask、启动时压缩、没有 hint file。
- MVCC 不回收历史版本。
- Raft 没有快照、日志截断、在线成员变更、leader lease。
- SQL 没有 ALTER TABLE、没有成本优化器。
- 查询结果和 Raft 扫描会整表缓冲。

读代码时不要把这些缺口当成“还没写完的生产功能”。它们是为了让核心路径可见而故意省略的。

入口：`README.md`、`docs/architecture/overview.md`。

## 00.2 分层职责

自底向上：

```text
toysql / Client
    → Server（SQL TCP + Raft TCP + 线程路由）
        → sql::execution::Session（解析、事务控制）
            → Planner / Optimizer / Executor
                → sql::engine::Raft（把存储操作编码成 Raft 命令）
                    → raft::Node（选举、复制、安全读）
                        → sql::engine::raft::State
                            → sql::engine::Local
                                → storage::MVCC
                                    → storage::Engine（Memory 或 BitCask）
```

每一层只解决一类问题：

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| `storage::Engine` | 字节 KV、有序扫描、可选落盘 | 表、事务、复制 |
| `storage::MVCC` | 版本、快照隔离、冲突 | SQL、Raft |
| `sql::engine::Local` | 表/行/索引映射到 MVCC | 解析、复制 |
| 解析/规划/执行 | SQL 文本变成行流 | 持久化、多数派 |
| Raft | 复制、线性一致读 | 事务隔离语义 |
| Server | 线程、TCP、通道 | SQL 语义 |

## 00.3 三个不同的 Engine

仓库里至少有三个都叫 engine 的东西，不要混：

1. `storage::Engine`（`src/storage/engine.rs`）  
   底层 KV：`get/set/delete/scan/flush`。

2. `sql::engine::Engine`（`src/sql/engine/engine.rs`）  
   SQL 存储：`begin` / `begin_read_only` / `begin_as_of`，真正工作在 `Transaction` 上。有 `Local` 和 `Raft` 两个实现。

3. `raft::State`（`src/raft/state.rs`）  
   Raft 状态机：`apply` 写命令、`read` 读命令。toyDB 的实现是 `sql::engine::raft::State`，内部再调 `Local`。

程序入口在 `src/lib.rs` 导出 `Client`、`Server`、`StatementResult`。二进制在 `src/bin/`：`toydb`、`toysql`、`toydump`、`workload`。

## 00.4 文档、源码、测试如何相互核对

阅读顺序：

1. `docs/architecture/` 建立地图。
2. 当前源码确认类型、方法和错误。文档里的 GitHub 行号可能指向旧提交。
3. `src/*/testscripts/` 与 `tests/scripts/` 用输入/预期输出固定行为。

Goldenscript 不是“示例注释”，而是可运行的行为契约。讲解时把脚本当行为示例；是否实际 `cargo test` 会在记录里单独标明。

示意图（例如架构 SVG、Raft 角色图）表达结构，不替代具体实现。
