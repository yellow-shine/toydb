# 05 事务生命周期与隔离边界

源码：`src/storage/mvcc.rs`。  
测试：`src/storage/testscripts/mvcc/` 的 begin、resume、冲突、rollback、bank、anomaly 系列。

## 05.1 开始、状态、恢复

`MVCC::begin` 分配新 version 并加入活跃集合。`begin_read_only` 不增加 `NextVersion`，用当前 NextVersion 作为只读上限。`begin_as_of(v)` 要求 `v` 已存在，恢复当时的 `TxnActiveSnapshot`。

`TransactionState` 可以序列化。`resume` 用它重建事务对象：读写事务会检查 `TxnActive(version)` 仍在，否则报“没有这个活跃事务”。这是 Raft SQL 引擎跨请求、跨 Leader 继续同一事务的基础。

## 05.2 写入与冲突

`set` 和 `delete` 都走 `write_version`。只读事务写会得到 `Error::ReadOnly`。

冲突检测：从 `min(active 里最小 version, 自己 version+1)` 扫到 `u64::MAX`，看该用户 key 是否已有 **对自己不可见** 的最新版本。有则 `Error::Serialization`，调用者必须重试整个事务。覆盖自己尚未提交的写入是允许的。

通过检查后写入：

- `Key::TxnWrite(version, user_key)`：记录本事务写过哪些用户 key，供回滚。
- `Key::Version(user_key, version)`：新版本值。

## 05.3 提交

读写事务 `commit`：

1. 删掉该 version 的全部 `TxnWrite` 记录。
2. 删除 `Key::TxnActive(version)`。

注释写明：**commit 不 flush**。持久性交给 Raft 日志。活跃标记一旦删掉，后来开始的事务就看不见这个 version 在 active 里，于是按可见性规则能读到这些写。已经开始、快照里仍含该 version 的事务继续看不见它们。

只读事务的 commit 是空操作。

## 05.4 回滚

回滚扫描 `TxnWrite`，删除对应的 `Key::Version` 和 `TxnWrite` 本身，再退出活跃集合。`TxnActiveSnapshot` 留下，因为时间旅行还要用“当时有哪些活跃事务”。

失败路径必须先收集 key 再删除：扫描迭代器借用着引擎，不能边扫边改。

## 05.5 只读与时间旅行

只读事务不分配独占 version，不能写。时间旅行用过去的 version + 当时的活跃快照。`as_of` 若大于等于当前 NextVersion，报 version 不存在。

历史查询看到的是“那个读写事务 **开始时** 的数据库”，不是“那个 version 号提交后的数据库”。这与 04.3 的 `version < self.version` 一致。

## 05.6 并发异常对照

仓库用脚本固定这些现象（MVCC 层与 SQL 层各有一份）：

| 现象 | toyDB SI 下 |
| --- | --- |
| 脏读 dirty read | 不会：未提交版本在对方的 active 快照里 |
| 脏写 dirty write | 不会：写不可见版本会 Serialization |
| 模糊读 / 不可重复读 | 快照内稳定；提交后的新事务才看见新值 |
| 读偏斜 read skew | 快照隔离本身就会在不同 key 上看到同一时刻的切面，脚本展示这种切面 |
| 幻读 phantom | 快照扫描同样受 version/active 约束 |
| 丢失更新 lost update | 后写冲突，需重试 |
| 写偏斜 write skew | **可以发生**：两个事务改不同 key，各自快照都合法 |

`anomaly_write_skew` 存在，正是为了说明 SI ≠ 可串行化。

## 05.7 SI、ACID 拆分、未实现的 GC

- **Atomicity**：提交时一次删掉活跃标记，整组写同时可见；回滚删掉本事务版本。
- **Consistency**：表约束在 SQL 执行层检查，不是 MVCC 层。
- **Isolation**：快照隔离，不是 SSI / 可串行化。
- **Durability**：MVCC 本身不 fsync；接入 Raft 后由日志提供。

历史版本永不回收。时间旅行因此没有上限，磁盘会一直涨。这是刻意简化。

不要把 MVCC version、Raft term、Raft log index、ReadSequence 当成同一个时钟。
