# 06 SQL 数据模型与表达式

源码：`src/sql/types/value.rs`、`src/sql/types/schema.rs`、`src/sql/types/expression.rs`。  
文档：`docs/architecture/sql-data.md`。  
测试：`src/sql/testscripts/expressions/`、`src/sql/testscripts/schema/`。

## 06.1 DataType、Value、Row

四种标量类型：`Boolean`、`Integer`（i64）、`Float`（f64）、`String`。没有复合类型、没有日期。

`Value` 多一个 `Null`。`Row` 是 `Vec<Value>`。`Rows` 是返回 `Result<Row>` 的迭代器。

执行期的一行就是这些 Rust 值。存盘时整行用 Bincode 编码，作为 MVCC 的 value。

## 06.2 NULL、NaN、比较的三套语义

代码里 `Value::Null == Value::Null` 为 true，NaN 也视为相等，`-0.0` 与 `0.0` 相等。这样 HashMap/BTree 才能索引它们。序列化时 `-0.0` 和 `-NaN` 会规范成正的，避免索引里出现两个“同一个”key。

SQL 语义在 `Expression::evaluate` 里另写：`NULL = NULL` 得到 `NULL`，不是 TRUE。过滤和 Join 把 `NULL` 当不匹配（与 `FALSE` 一起丢掉行）。

不要用 Rust 的 `PartialEq` 去理解 `WHERE`。

## 06.3 表与列

`Table`：名字、单个主键列下标、列向量。没有库名，没有独立的 named index 对象。

`Column` 字段：类型、nullable、default、unique、index、references（外键指向的表名）。主键隐含 unique、非空、且 **没有** 二级 index 标记（主键本身就是主索引）。unique / 外键列会强制建二级索引。

表结构创建后不能改：没有 ALTER，没有 CREATE INDEX。

## 06.4 校验分两层

`Table::validate` 查表级不变量：主键存在、列名合法、外键目标表存在且类型匹配。需要 `Catalog`。

`Table::validate_row` 查一行：类型、非空、主键冲突、唯一约束、外键是否指向存在的行。需要 `Transaction` 去查其他行。`insert` 与 `update` 调用它的方式略有不同（是否允许“自己那一行”）。

## 06.5 表达式树

`Expression` 是求值树：常量、列下标 `Column(usize)`、算术、比较、逻辑、函数。`1 + 2 * 3` 是 `Add(1, Multiply(2, 3))`。

`evaluate(Some(&row))` 递归求值。列下标从当前行取。SQL 的 NULL 传播、比较、LIKE 在这里实现；加减乘除常分派到 `Value` 的运算方法。

解析器产出的是 `ast::Expression`（带列名）；规划器把它变成这里的 `Expression`（带列下标）。两者不是同一种类型。
