# 07 SQL 本地存储与索引

源码：`src/sql/engine/engine.rs`、`src/sql/engine/local.rs`、`src/sql/types/schema.rs`。  
文档：`docs/architecture/sql-storage.md`。  
测试：`src/sql/testscripts/schema/`、`src/sql/testscripts/writes/`。

## 07.1 SQL Engine 不是 KV Engine

`sql::engine::Engine` 只有 `begin` / `begin_read_only` / `begin_as_of` / `session()`。行操作在 `Transaction` 上，并且是 **批量** 的：一次 `insert(rows)`、一次 `delete(ids)`，好摊掉 Raft 往返。

`Local<E>` 包着 `mvcc::MVCC<E>`。测试常用 Memory；节点上的状态机也是 Local，只是外面再套 Raft。

## 07.2 key 布局

```text
Key::Table(name)                    → Table schema
Key::Index(table, column, value)    → BTreeSet<主键>
Key::Row(table, 主键)               → Row
```

Keycode 按枚举变体排序，所以所有表结构在前，然后索引，然后行。同一张表的行按主键值排序。

`KeyPrefix::Row("movies")` 用来前缀扫描整张表。这就是 01 和 03 在 SQL 层的落地。

这些 SQL key 再被 MVCC 包一层 `Key::Version(sql_key, version)`。扫描一张表 = MVCC 前缀扫描 + 可见性过滤。

## 07.3 点查、全表扫、二级索引

- 主键点查：`Key::Row(table, id)` 的 MVCC get。
- 全表扫：`scan_prefix(KeyPrefix::Row(table))`，可选再按表达式过滤。过滤在本地求值，`NULL/FALSE` 丢掉行。
- 二级索引：读 `Key::Index(table, col, value)` 得到主键集合，再 `get` 那些行。

`lookup_index` 一次可查多个索引值，返回合并后的主键集合。

## 07.4 插入、更新、删除

插入：`validate_row` → 写 Row → 把主键加入每个二级索引的集合。

删除：先查有没有别的表（或本表其他行）通过外键引用这些主键；有则报错。然后从二级索引集合里拿掉该主键，集合空则删掉索引 key，最后删行。

更新：主键变了就删旧插新。主键不变则校验后更新索引（值没变则跳过）再覆盖行。

## 07.5 Catalog

`create_table`：已存在则报错，`Table::validate`，再写 `Key::Table`。

`drop_table`：不存在且非 `IF EXISTS` 则报错；被其他表引用则报错；删 schema、该表所有行、所有二级索引条目。

`list_tables` 是 `KeyPrefix::Table` 的前缀扫描。DDL 也在事务里，可以回滚。`create_table_transaction` 等脚本覆盖这一点。

## 07.6 约束与并发边界

类型、非空、默认值、唯一、外键在 Local 事务方法里检查。并发下两个事务插同一主键：MVCC 会 Serialization，或后提交的 `validate_row` 看见已提交的行。不要假设“接口校验一次就永远不会出现违反约束的已提交状态”——冲突方必须重试。

外键列都有二级索引，删除时才能用索引找引用，而不必扫来源表。
