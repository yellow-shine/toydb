# 10 查询执行器

源码：`src/sql/execution/executor.rs`、`src/sql/execution/join.rs`、`src/sql/execution/aggregator.rs`。  
文档：`docs/architecture/sql-execution.md`。  
测试：`src/sql/testscripts/queries/`、`src/sql/testscripts/writes/`。

## 10.1 拉取式执行

`Executor::execute` 按 `Plan` 根分派。查询节点走 `execute_node`，返回 `Rows`。父节点调用子迭代器的 `next()` 才拉下一行。错误随 `Result` 往上走，不在中途吞掉。

这是火山模型（iterator model），不是把整棵树物化成一张大表（Order/Aggregate/HashJoin 除外，它们必须缓冲）。

## 10.2 扫描、查找、过滤、投影

- `Scan`：`Transaction::scan(table, filter)`，过滤可下推到存储。
- `KeyLookup`：主键批量 `get`。
- `IndexLookup`：先 `lookup_index` 再 `get` 行。NULL/NaN 在索引里按代码相等语义匹配，以便 `IS NULL`。
- `Filter`：`predicate.evaluate`；`TRUE` 留下，`FALSE`/`NULL` 丢掉。
- `Projection`：对每行求一组表达式。
- `Remap`：按目标下标搬列。

## 10.3 Join

默认计划是 `NestedLoopJoin`：对每一行左，重放整个右（右迭代器可 clone）。谓词为真则输出拼接行。`outer=true`（LEFT JOIN）在右无匹配时补 NULL。

`HashJoin`：把右表按连接列建成内存 HashMap，再探查左表。只用于单列等值连接。右表完全进内存。

CROSS JOIN 就是没有谓词的 nested loop。内连接不输出 NULL 补齐行。

谓词得到非布尔值是输入错误。`NULL` 谓词与 Filter 一样视为不匹配。

## 10.4 聚合

`Aggregator` 用 `BTreeMap<分组键, 累加器>`。每行先求 GROUP BY 表达式当桶，再更新 COUNT/SUM/AVG/MIN/MAX。

没有输入行且没有 GROUP BY 时，仍输出一行空累加器，例如 `SELECT COUNT(*) FROM t WHERE FALSE` 得到 0。有 GROUP BY 且无行则输出空集。

COUNT 忽略 NULL（COUNT(*) 计行）。SUM 在全 NULL 时得到 NULL。细节见 `Accumulator`。

## 10.5 排序与 LIMIT

`Order` 把全部行读进内存再排。`Limit` 是 `take`，`Offset` 是 `skip`。LIMIT/OFFSET 本身流式，但若下面有 Order，仍先排序整个集合。

HashJoin、Aggregate、Order 都是内存算法，没有外存溢写。

## 10.6 写入执行

Insert：从 source 拉行，按 column_map/默认值补齐，调用 `txn.insert`。  
Update：拉行，求更新表达式，`txn.update`。  
Delete：拉行，取出主键，`txn.delete`。  
DDL：直接 `create_table` / `drop_table`。

结果是受影响行数或表名，不是行流。约束错误变成 `InvalidInput`。
