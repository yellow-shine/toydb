# 09 Planner 与名称解析

源码：`src/sql/planner/plan.rs`、`src/sql/planner/planner.rs`。  
文档：`docs/architecture/sql-planner.md`。

## 09.1 三棵树

| 树 | 类型 | 含义 |
| --- | --- | --- |
| AST | `ast::Statement` | 语法 |
| 表达式 | `sql::types::Expression` | 可对一行求值 |
| 计划 | `Plan` / `Node` | 如何产生行 |

`Plan` 根节点是动作：CreateTable、DropTable、Insert、Update、Delete、Select。`Select` 下面是 `Node` 树：Scan、Filter、Projection、Join、Aggregate、Order、Limit…

数据从叶子流向根。EXPLAIN 打印的就是这棵树。

## 09.2 Scope 与名称

Planner 用 Catalog 取表结构，用 `Scope` 跟踪当前节点能看见的表别名和列。`FROM movies m JOIN genres g` 把两套列放进 scope。列名歧义（两边都有 `id` 且未限定）会报错。`*` 展开成当前可见列。

不存在的表/列在规划期失败，不会拖到执行期才发现（写语句的值表达式除外，有些检查在执行时 `validate_row`）。

## 09.3 列名变成下标

规划后，`Expression::Column(3)` 表示当前行的第 4 列。Join 把左右行拼在一起，右表列下标要加上左表列数。Projection 之后列集合变了，后面的表达式要用新下标。`Remap` 节点专门搬列、丢列、补 NULL。

## 09.4 SELECT 子句的计划顺序

文本顺序不是执行顺序。典型未优化计划：

```text
Scan → Join → Filter(WHERE) → Aggregate → Filter(HAVING) → Projection → Order → Offset → Limit
```

WHERE 在分组前，HAVING 在分组后。ORDER/LIMIT 在投影附近，具体以 `build_select` 为准。常量 LIMIT/OFFSET 在规划时求成 `usize`。

## 09.5 写语句与 DDL

DELETE：Scan（可带 WHERE）→ 用主键列下标删。  
INSERT：Values 节点；若指定了列名，建 `column_map`（表列下标 → 值下标），缺的列用默认值。  
UPDATE：Scan 出完整行，再附列更新表达式。  
CREATE TABLE：规划期确认有且仅有一个主键，填好 nullable/default/index 标志；其余校验留给执行。

合法语法仍可能规划失败：没有主键、未知列、列重复出现。

## 09.6 EXPLAIN、格式化、变换

`Plan::optimize` 对数据节点跑 `OPTIMIZERS`。`Node::transform` / `transform_expressions` 做前序或后序递归变换，优化器用它们。`Display` 打出缩进树，就是 EXPLAIN 的输出。

Session 在只读隐式事务里 `Plan::build(...).optimize()`，不执行。
