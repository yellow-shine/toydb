# 08 Lexer、Parser 与 AST

源码：`src/sql/parser/lexer.rs`、`src/sql/parser/ast.rs`、`src/sql/parser/parser.rs`。  
文档：`docs/architecture/sql-parser.md`、`docs/sql.md`。

## 08.1 Token

Lexer 把字符变成 `Token`：`Number`、`String`、`Ident`、`Keyword`、标点和运算符。标识符默认小写；带引号的保持原样。字符串处理转义。数字是字符串形式，正负号是独立 token。

token 持有 `String` 而不是借输入切片，因为要改写（小写、去引号）。这些所有权反正会进入 AST。

无法识别的字符变成 `InvalidInput`。

## 08.2 AST 保留什么、不保留什么

`ast::Statement` 是语法结构：BEGIN/COMMIT/ROLLBACK、EXPLAIN、CREATE/DROP TABLE、INSERT/UPDATE/DELETE、SELECT。SELECT 里有 select 列表、FROM/JOIN、WHERE、GROUP BY、HAVING、ORDER BY、LIMIT/OFFSET。

AST 知道“有一张叫 movies 的表、一列叫 title”，不知道这张表是否存在，也不知道 `title` 是第几列，也不知道该用 HashJoin 还是 NestedLoopJoin。那是 Planner 的事。

AST 里的表达式仍带列名；执行期 `sql::types::Expression` 带列下标。

## 08.3 解析器怎么吃 token

`Parser::parse` 要求整段输入是 **一条** 语句，末尾分号可选，后面不能再有 token。

内部用 `Peekable<Lexer>`：`next`、`peek`、`next_if`、`skip`。`parse_statement` 按第一个关键字分派。失败返回 `InvalidInput`，不尝试自动修复。

## 08.4 运算符优先级

表达式用分层函数：逻辑 OR/AND/NOT、比较、加减、乘除、一元、主键（字面量、标识符、括号、函数）。`^` 等在更里层。`src/sql/testscripts/expressions/op_precedence` 固定优先级。括号只影响树形状，不改变 token。

## 08.5 语句入口与方言范围

能解析不等于能执行。方言以 `docs/sql.md` 为准：四种类型、有限 JOIN、聚合、事务、EXPLAIN、`BEGIN READ ONLY AS OF`。没有子查询、没有窗口函数、没有 ALTER。

`BEGIN`/`COMMIT`/`EXPLAIN` 会进 AST，但 Planner 遇到它们会 panic——Session 必须先截走这些语句。
