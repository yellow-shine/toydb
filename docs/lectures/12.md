# 12 SQL 会话与事务管理

源码：`src/sql/execution/session.rs`、`src/sql/engine/engine.rs`。连接结束见 `src/server.rs`。  
测试：`src/sql/testscripts/transactions/`、`tests/scripts/errors`。

## 12.1 Session 持有什么

```rust
pub struct Session<'a, E: Engine<'a>> {
    engine: &'a E,
    txn: Option<E::Transaction>,
}
```

一个 SQL 连接对应一个 Session。显式事务时 `txn` 为 Some；自动提交时为 None，每条语句自己开隐式事务。

## 12.2 自动提交与显式事务

`BEGIN`：已在事务中则报错。按 `READ ONLY` / `AS OF` 调用 `engine.begin*`，保存事务，返回 `StatementResult::Begin(state)`。不能 `BEGIN` 读写且指定 version。

`COMMIT`/`ROLLBACK`：没有事务则报错；`take()` 出事务再提交或回滚。

其他语句走 `with_txn`：有显式事务就用它；否则开隐式事务——SELECT 用只读，写用读写——成功则 commit，失败则 rollback。隐式事务每次都是额外的 Raft 往返（begin+语句+commit）。不自动重试 `Serialization` 或 `Abort`。

## 12.3 语句流水线

```text
Parser::parse
  → BEGIN/COMMIT/ROLLBACK 在 Session 处理
  → EXPLAIN：with_txn(read_only) 里 build+optimize，不 execute
  → 其余：build → optimize → execute → StatementResult
```

SELECT 结果在 `TryFrom<ExecutionResult>` 时 **整表收集** 成 `Vec<Row>`，再发给客户端。

## 12.4 失败与清理

语句错误：隐式事务已 rollback；显式事务仍在，是否还能继续用取决于错误类型（例如 Serialization 通常应结束事务，但 Session 不会自动清掉 `self.txn`，除非是 COMMIT/ROLLBACK 路径）。Drop Session 时若还有显式事务，会 rollback，失败只打日志。

`InvalidInput` 是用户/SQL 错误；`Abort` 是 Raft 选主等，客户端应重试；`Serialization` 是写冲突，应重试整个事务。不能把三者当成同一种失败。

## 12.5 不把 version 交给用户操作

SQL 用户写 `BEGIN` / `COMMIT`。Session 和 SQL Engine 把这映射成 MVCC begin/commit。`AS OF` 把一个数字 version 传进去，但用户从不直接构造 `Key::Version`。客户端 `Client.txn` 只是把 `Begin` 返回的状态记下来方便显示，真正的事务状态在服务端 Session 里（Raft 模式下每条命令还会带上 `TransactionState` 重建 MVCC 事务，见第 15 章）。
