# 11 启发式优化器

源码：`src/sql/planner/optimizer.rs`、`src/sql/planner/plan.rs`、`src/sql/types/expression.rs`。  
文档：`docs/architecture/sql-optimizer.md`。  
测试：`src/sql/testscripts/optimizers/`。

## 11.1 规则优化，不是成本优化

顺序固定：

```text
ConstantFolding → FilterPushdown → IndexLookup → HashJoin → ShortCircuit
```

没有统计信息，没有代价模型。每条规则是树变换：等价（或在 SQL 语义下更省）的另一棵 `Node`。

前序/后序很重要。常量折叠用后序，先折叶子。短路也用后序，好把 `Nothing` 往上吸。

## 11.2 常量折叠

没有 `Column(_)` 的子树当场 `evaluate(None)` 换成常量。`1+2*3-foo` 变成 `7-foo`。

逻辑化简：`x AND FALSE` → `FALSE`，`x OR TRUE` → `TRUE`。不重排加减法，所以 `(1+foo)-2` 不会变成 `foo-1`。NULL 仍按 SQL 三值逻辑求值，不会被当成普通 false。

## 11.3 过滤下推与 CNF

`into_cnf` 把谓词变成 AND 的列表，于是每个合取项可以单独移动。Filter 的谓词能 AND 进下面的 Filter、NestedLoopJoin 或 Scan。

Join 下推只移动 **只引用一侧列** 的合取项。两侧都引用的条件留在 Join 上。列下标在下推时要重映射到子节点的行布局。

下推的目的是少读行、少 Join、以及让后面的 IndexLookup 能看见 Scan 上的谓词。Raft 扫描会缓冲整表，下推尤其重要。

## 11.4 索引查找

假定谓词已在 Scan 上。在 CNF 里找 `column = value`（或 OR 链）且该列是主键或二级索引，则把 Scan 换成 `KeyLookup` 或 `IndexLookup`。剩下的合取项变成外层 Filter。

`WHERE id=1 OR id=7` 可以变主键查找；`AND released>=2000` 仍过滤。

## 11.5 Hash Join

`NestedLoopJoin` 的谓词若是单列 `Column = Column`，改成 `HashJoin`，并修正右列下标（Join 谓词用的是拼接行下标）。非等值、多列、表达式连接保持 nested loop。

## 11.6 短路

`Filter FALSE`、空 Values、对 Nothing 的投影等变成 `Nothing`（保留列名给表头）。这不是“更快所以正确”，而是恒假/恒空的代数化简。测试脚本逐步打印每条规则之后的计划，用来看等价变换，不是性能基准。
