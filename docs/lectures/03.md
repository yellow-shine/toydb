# 03 编码与 key 布局

源码：`src/encoding/mod.rs`、`src/encoding/bincode.rs`、`src/encoding/keycode.rs`、`src/encoding/format.rs`。  
文档：`docs/architecture/encoding.md`。

## 03.1 序列化边界

底层引擎只存 `Vec<u8>`。上层的枚举、结构体、数字必须先变成字节。toyDB 分成两套：

- `encoding::Key`：Keycode，用于 **会被排序和范围扫描的 key**。
- `encoding::Value`：Bincode，用于 value、网络消息、Raft 命令结果。

两者都走 Serde。`Key::encode/decode` 和 `Value::encode/decode` 只是固定配置的包装，避免每处手写序列化参数。

编码不包含业务语义。同样的字节，MVCC 当成 `Key::Version`，SQL 当成 `Key::Row`，Raft 当成 `Key::Entry`。调用者必须知道自己写进去的类型。

## 03.2 Bincode 作 value 编码

`src/encoding/bincode.rs` 使用 `bincode::config::standard()`。编码失败会 panic（视为数据结构有问题）；解码失败变成 `Error`。

`maybe_deserialize_from` 在 TCP 对端关闭时返回 `Ok(None)`，供 Server/Client 读循环使用。

Bincode 不是自描述格式，也不保证跨版本兼容。结构体字段顺序变了，旧字节就会解错。toyDB 接受这个限制。value 不需要保序，所以不必用 Keycode。

## 03.3 为什么普通编码不能当 key

存储按 **原始字节** 排序。Bincode 给字符串加长度前缀后，`"key"` 会排在 `"house"` 前面，因为长度 `3 < 5`。小端整数会让大数排在小数前面。有符号整数的符号位会让正数排在负数前面。

因此 key 必须用保序编码：编码后的字节序 = 原值的逻辑序。

## 03.4 Keycode 规则

`src/encoding/keycode.rs`：

| 类型 | 编码 |
| --- | --- |
| `bool` | `00` / `01` |
| `u64` | 大端 8 字节 |
| `i64` | 大端，翻转符号位，让负数排在正数前 |
| `f64` | 大端 IEEE 754；正数翻符号位；负数翻全部位 |
| `Vec<u8>` / `String` | `00` 转义为 `00 ff`，以 `00 00` 终止 |
| 序列 / 元组 | 直接拼接元素 |
| 枚举 | 变体序号 `u8`，再跟内容 |

字符串不能用长度前缀，否则短串可能排在长串后面。用终止符后，公共前缀下短串排在长串前面：`"a"` < `"ab"`。

复合 key 按字段从左到右比较。这让 `Key::Row("movies", id)` 先按表名聚在一起，再按主键排序。

枚举变体序号也参与排序。MVCC 里 `NextVersion` 在 `Version` 前面，因为变体下标更小。SQL 里 `Table`、`Index`、`Row` 同样按变体分开。

## 03.5 prefix_range

```rust
pub fn prefix_range(prefix: &[u8]) -> (Bound<Vec<u8>>, Bound<Vec<u8>>) {
    let start = Bound::Included(prefix.to_vec());
    let end = match prefix.iter().rposition(|&b| b != 0xff) {
        Some(i) => Bound::Excluded(
            prefix.iter().take(i).copied().chain(std::iter::once(prefix[i] + 1)).collect(),
        ),
        None => Bound::Unbounded,
    };
    (start, end)
}
```

上界是“比该前缀大的下一个前缀”。末尾是 `0xff` 时向左进位；全部是 `0xff` 时没有有限上界，扫描到引擎末尾。

MVCC 的 `scan_prefix` 会先把 `KeyPrefix::Version(prefix)` 编码出来，再 **去掉末尾的 `00 00` 终止符**，否则只能匹配精确 key 而不是 key 前缀。

`src/storage/testscripts/engine/scan_prefix` 覆盖前缀扫描。Keycode 文件内还有往返与排序测试。

## 03.6 可读格式化

`encoding::format` 把原始字节解成测试输出，例如 `"foo" → "bar"`，或 Raft/MVCC/SQL 的逻辑 key。Goldenscript 的 `Get`/`Dump` 走这些 Formatter，所以测试里看到的是逻辑形态，不是一长串 hex（BitCask `dump` 会额外打印 hex）。
