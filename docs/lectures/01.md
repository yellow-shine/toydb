# 01 有序 KV 与 Memory

源码：`src/storage/engine.rs`、`src/storage/memory.rs`。  
测试：`src/storage/testscripts/engine/`。

## 01.1 为什么除了 get/set 还需要有序扫描

存储层只认识字节：

```rust
pub struct Memory(BTreeMap<Vec<u8>, Vec<u8>>);
```

`get` 要求调用者已经知道完整 key。表扫描、MVCC 版本扫描、Raft 日志后缀扫描都不满足这个前提。key 按字典序排列后，一组相关数据会落在连续区间里，于是 `scan` 就能按范围遍历。

`scan_prefix` 不是另一套算法：

```rust
fn scan_prefix(&mut self, prefix: &[u8]) -> Self::ScanIterator<'_>
where
    Self: Sized,
{
    self.scan(keycode::prefix_range(prefix))
}
```

Memory 直接把范围交给 `BTreeMap::range`，每次 `next()` 才复制一对 key/value。

`src/storage/testscripts/engine/scan` 写入 `a,b,ba,bb,c,C` 后，全量扫描顺序是 `C, a, b, ba, bb, c`：这是字节字典序，不是插入顺序。`b..bb` 得到 `b, ba`；`b..=bb` 再包含 `bb`。

**带走：get 找一个已知 key；有序 scan 找一组 key。上层通过设计 key 把业务集合变成区间。**

## 01.2 点查与写入契约

接口：

```rust
fn delete(&mut self, key: &[u8]) -> Result<()>;
fn get(&mut self, key: &[u8]) -> Result<Option<Vec<u8>>>;
fn set(&mut self, key: &[u8], value: Vec<u8>) -> Result<()>;
```

Memory 实现：

- `set` 是 `BTreeMap::insert`：同一 key 后写覆盖前写。
- `delete` 是 `remove`：key 不存在也返回 `Ok(())`。
- `get` 返回 `Ok(Some(value))`、`Ok(None)` 或（在其他引擎上）`Err`。

空 value `vec![]` 与不存在不是一回事。`get` 对空 value 返回 `Some([])`，对缺失返回 `None`。`src/storage/testscripts/engine/point` 覆盖这些点操作。

`Result` 是 `std::result::Result<T, crate::error::Error>`。Memory 的这些路径几乎不会失败，但 trait 必须容纳磁盘 IO。

## 01.3 迭代器、正反向扫描、scan 与 scan_dyn

`ScanIterator` 要求：

```rust
pub trait ScanIterator: DoubleEndedIterator<Item = Result<(Vec<u8>, Vec<u8>)>> {}
```

因此扫描可以 `next()` 正向，也可以 `next_back()` 反向。`scan reverse=true` 的测试就是反向消耗这个迭代器。

关联类型：

```rust
type ScanIterator<'a>: ScanIterator + 'a
where
    Self: Sized + 'a;
```

`'a` 表示迭代器借用引擎。`where Self: Sized` 把这个方法从 trait object 里拿掉：`dyn Engine` 不能直接调用带 `impl RangeBounds` 的 `scan`。

所以还有：

```rust
fn scan_dyn(&mut self, range: (Bound<Vec<u8>>, Bound<Vec<u8>>))
    -> Box<dyn ScanIterator + '_>;
```

Raft 日志把引擎存成 `Box<dyn storage::Engine>`，范围扫描走 `scan_dyn`。Memory / BitCask 的 `scan_dyn` 只是 `Box::new(self.scan(range))`。

## 01.4 单使用者、flush 与 status

注释写明：为简单起见，所有方法（包括读）都要 `&mut self`，一次只服务一个使用者。Raft 状态机本来就是串行 apply，这个限制可以接受。`Engine: Send` 是为了把引擎移到别的线程，不是为了并行读写同一个引擎。

Memory 的 `flush` 是空操作：数据只在进程内存里。BitCask 的 `flush` 才会 `sync_all`（测试构建除外）。

`Status` 统计 live keys、逻辑大小、磁盘大小、live 磁盘大小。Memory 的 `disk_size` 和 `live_disk_size` 都是 0。`garbage_disk_size()` 是两者之差。`src/storage/testscripts/memory/status` 覆盖 Memory 的统计。
